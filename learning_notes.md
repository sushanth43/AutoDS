# Phase 0 – Product Design

## Step 0.5 – Project Vision

### Engineering Decision 001

**Decision**

Build AutoDS in two stages.

### Stage 1 (Current)

Develop an autonomous data science platform where the user uploads a dataset and the system automatically:

- Validates the dataset
- Cleans the data
- Performs Exploratory Data Analysis (EDA)
- Performs Feature Engineering
- Detects the Machine Learning problem
- Trains multiple ML models
- Compares model performance
- Explains predictions
- Generates reports
- Displays results in an interactive dashboard

### Stage 2 (Future)

Transform AutoDS into an AI-powered Data Science Assistant capable of understanding natural language queries and interacting conversationally with the dataset.

### Why this decision?

Building the core data science engine first provides a strong and reusable foundation. Once the engine is complete, adding an AI assistant becomes significantly easier because the assistant will simply invoke the capabilities already built.

## Engineering Decision 002

**Decision**

The primary target users of AutoDS are Data Scientists and Machine Learning Engineers.

However, the interface will remain simple and intuitive so that beginners and students can also use the platform without prior experience.

### Why this decision?

This project is intended to demonstrate professional engineering practices and machine learning workflows suitable for industry-level roles.

Designing for professionals encourages a scalable architecture, while maintaining a beginner-friendly interface improves usability and accessibility.

## Engineering Decision 003

**Decision**

AutoDS Version 1.0 will focus on building a complete autonomous data science platform.

### Included in Version 1.0

- CSV Upload
- Dataset Validation
- Data Profiling
- Data Cleaning
- Exploratory Data Analysis (EDA)
- Feature Engineering
- Automatic Machine Learning
- Model Comparison
- Explainability (SHAP)
- Interactive Dashboard
- PDF Report Generation
- FastAPI Prediction API

### Future Versions

- AI Chat Assistant
- Multi-Agent System
- Docker
- MLflow
- Authentication
- Enterprise Features

### Why this decision?

Building a strong and complete core platform first provides a stable foundation for future enhancements while ensuring that Version 1.0 is already a professional, usable product.

## Engineering Decision 005

**Decision**

AutoDS will follow a modular pipeline architecture.

### Overall Flow

User
↓
Upload Dataset
↓
Data Ingestion
↓
Data Profiling
↓
Data Cleaning
↓
Feature Engineering
↓
AutoML Engine
↓
Model Evaluation
↓
Explainability
↓
Dashboard & Report
↓
Prediction API

### Why this architecture?

Each module has a single responsibility and performs one well-defined task. This modular design makes the project easier to understand, test, maintain, and extend with future features such as AI assistants and multi-agent systems.

## Engineering Decision 006

The README is the entry point to the repository. It explains the project's purpose, current status, and future direction to anyone visiting the repository, including recruiters and collaborators.

## Engineering Decision 007

**Decision**

Create a `.gitignore` file at the beginning of the project.

### Why?

Some files are automatically generated by Python, VS Code, and the operating system. These files do not belong in version control because they are either temporary or specific to one computer.

The `.gitignore` file tells Git which files and folders should be ignored.
